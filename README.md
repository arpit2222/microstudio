# MicroStudio 🎬

**MicroStudio** is a next-generation decentralized studio platform built for the **Backblaze Generative Media Hackathon**. It leverages AI to generate, cast, crowdfund, and distribute film & TV content—all powered by Backblaze B2 for massive media storage and Genblaze for multi-modal AI generation.

MicroStudio isn't just a video generator; it's a complete **ecosystem**. It enables creators to pitch ideas, generate AI pilots, secure funding via Web3 royalty shares, and cast human talent—using ethical AI pipelines and cryptographically backed data provenance.

---

## 🌟 Features

- **Multi-Modal AI Pilot Generation**: Enter a premise, and our orchestrator automatically generates a script, scene videos, voiceovers, and a musical score, compositing them into a final pilot.
- **TikTok-Style Discovery Feed**: A vertical-scrolling, snap-to-play feed where users discover, like, and share pilots. Engagement scores determine which pilots get produced.
- **Ethical AI Casting Marketplace**: Creators can open casting calls. Actors can apply and explicitly consent to having their likeness tested via AI. 
- **AI Promo Engine**: Once a pilot is produced, creators can click a button to let Genblaze automatically cut a punchy 30-second trailer with captions, which dynamically replaces the full video in the discovery feed.
- **Web3 Royalty Crowdfunding**: Fans can back in-progress pilots and receive a fractional royalty share of future ad revenue and syndication deals via smart contracts.
- **Premium OTT Player**: A Netflix-style viewing experience for fully produced series, featuring a hero player and interactive sidebars to toggle between raw AI assets, trailers, and the final cut.
- **Trust & Safety Gate**: Lightweight content moderation blocks harmful or hateful prompts from triggering the AI generation pipeline, ensuring platform safety.

## 🏗️ Architecture

MicroStudio uses a modern Orchestrator-Worker pattern:
- **Frontend / Orchestrator**: Next.js 14 (App Router) + TypeScript + Tailwind CSS.
- **Database**: PostgreSQL (managed via Prisma ORM) for relational mapping of Projects, Talent, Casting Calls, and Engagements.
- **AI Worker**: A Python FastAPI microservice that implements the `genblaze` SDK to chain various AI models, process media with `moviepy`, and composite the final assets.
- **Storage Layer**: Backblaze B2 via the AWS S3-compatible API.

---

## ☁️ Powered by Backblaze B2

MicroStudio relies on **Backblaze B2** as the foundational storage layer for the massive volume of high-fidelity media generated by AI pipelines. We treat B2 as true infrastructure, not just a bucket.

- **What's Stored**: Every individual step of the AI generation pipeline (scripts, raw audio stems, raw video scenes, thumbnails, final composites, and actor reference media).
- **How it's Stored**: We use the official `@aws-sdk/client-s3` to interact with B2's S3-compatible API. Uploads are handled by our Next.js orchestrator, which generates signed URLs on the fly for secure streaming.
- **Why B2?**: Generative AI pipelines create *massive* amounts of intermediate files. A single 1-minute pilot might require 10 video generations, 5 audio generations, and multiple composite renders. B2 provides the immense, cost-effective bandwidth and storage scalability required to make a generative-media studio economically viable.
- **Advanced B2 Nuance**:
  - **Cloudflare Bandwidth Alliance**: Because our TikTok-style feed generates heavy read traffic from autoplaying videos, routing this delivery through the Bandwidth Alliance provides free egress, keeping operational costs exceptionally low.
  - **Lifecycle Rules**: We can configure bucket lifecycle rules to auto-archive raw generation stems (audio/video fragments) to B2's coldest tier after 30 days, keeping active storage focused only on the final composited pilots.
  - **Scoped Application Keys**: We utilize fine-grained application keys mapped exactly to the required bucket for maximum security.

## 🧠 Powered by Genblaze Pipeline API & GMI Cloud

Our Python worker leverages the **Genblaze Pipeline API** to orchestrate a complex, multi-model pipeline without hardcoding provider logic. Because different models excel at different tasks, we chain them using **GMI Cloud** credits:
1. **Scripting**: Genblaze calls `gmi-llama-3` (via GMI Cloud) to expand a short premise into a multi-scene screenplay.
2. **Video Generation**: The script scenes are passed to `gmi-stable-video` to generate the visual B-roll.
3. **Voice & Narration**: The dialogue is sent to `gmi-audio-v1` for emotional text-to-speech.
4. **Scoring**: `gmi-music-v1` is used to generate a thematic background score.
5. **Compositing**: The Python service uses `moviepy` to stitch the video, voice, and music together, finally uploading the composite to Backblaze B2.
- **Resilience**: Our orchestrator explicitly wraps these generation calls in a retry/fallback loop, handling timeouts gracefully.

## 🛡️ AI Content Provenance & Ethical Safeguards

A core pillar of MicroStudio is ensuring that the use of Generative AI is ethical, traceable, and consensual.

### 1. Data Provenance & "Behind the Scenes"
Every asset uploaded to Backblaze B2 includes **Provenance Metadata** injected directly into the Prisma database and the B2 Object metadata. This includes:
- A **SHA-256-verified provenance manifest** ensuring the asset wasn't tampered with.
- The exact prompt used.
- The specific model/provider that generated it (e.g., `gmi-llama-3`).
- The timestamp of generation.
**Verification**: We expose this data directly in the UI! When watching a pilot on the OTT Player page, a "Provenance & Architecture" tech panel displays the exact B2 Object Key and Genblaze source model used for the video.

### 2. Strict Consent Gating for Actor Likeness
The standout **AI Casting Preview** feature allows creators to generate a mockup of an actor performing their script before casting them. However, this is strictly gated by our Ethical AI Engine:
- **Opt-In Only**: Actors must navigate to their settings (`/talent/[userId]/settings`) and actively toggle `consentForAIGeneration` to `true`.
- **The API Bouncer**: The generation endpoint (`POST /api/applications/[id]/preview`) queries the database *before* passing any reference media to Genblaze. If consent is denied, the API throws a `403 Forbidden` and the creator is shown a strict privacy alert. Actors retain all underlying rights to their likeness.

## 🚀 Setup Instructions

### Prerequisites
- Node.js 20+
- Python 3.10+
- PostgreSQL (Local or Cloud, e.g., Neon/Supabase)
- A Backblaze B2 Account

### 1. Environment Variables
Create a `.env` file in the root directory:
```env
# Database
DATABASE_URL="postgresql://user:pass@localhost:5432/microstudio"

# Backblaze B2
B2_ENDPOINT_URL="https://s3.us-west-004.backblazeb2.com"
B2_REGION="us-west-004"
B2_KEY_ID="your_key_id"
B2_APPLICATION_KEY="your_application_key"
B2_BUCKET_NAME="your_bucket_name"

# Genblaze
GENBLAZE_API_KEY="your_genblaze_key"
```

### 2. Database Setup & Seeding
Apply the schema and seed the mock data:
```bash
npx prisma migrate dev
npx tsc prisma/seed.ts
node prisma/seed.js
```

### 3. Start the AI Worker (Python)
```bash
cd python-service
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

### 4. Start the Next.js Orchestrator
```bash
npm run dev
```
Navigate to `http://localhost:3000` to begin!

## 📝 Genblaze SDK Feedback (Bonus Prize Submission)

*This is a draft for submission to the Genblaze GitHub Issues page for the feedback prize track:*

**Title:** Feedback: Enhancing Timeout Handling & Multi-Modal Type Definitions

**Feedback:**
While building MicroStudio—a robust orchestrator that chains text, video, and audio generation—we stress-tested the Genblaze SDK heavily. The developer experience was fantastic, especially the unified API surface for models like Claude and Runway. However, we encountered two areas for improvement:
1. **Resilience & Timeouts**: Generative video models (like Gen-3) can take significantly longer than text endpoints. The SDK currently lacks granular, per-provider timeout controls. Exposing a `timeoutMs` configuration at the individual model call level (rather than relying strictly on the global HTTP client timeout) would help us implement tighter fallback logic when a specific provider hangs.
2. **TypeScript Definitions for Compositing**: When fetching multi-modal output, the TS definitions for the return payloads were occasionally opaque regarding the raw buffer vs. stream types. Standardizing the response interface for binary assets (e.g., standardizing on `ReadableStream` or `Buffer` across all audio/video providers) would massively speed up downstream tasks like saving those assets directly to S3/Backblaze B2.

Overall, excellent SDK that made this complex orchestration possible in a weekend!
